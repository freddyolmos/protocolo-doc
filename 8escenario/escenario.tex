\section{Escenario de aplicación y validación}
\markboth{Escenario}{Escenario}

El sistema se plantea para sesiones individuales de práctica con un cubo Rubik 3 $\times$ 3 físico. El usuario objetivo es un practicante que conoce la resolución básica del cubo y desea ejercitar casos seleccionados de la etapa F2L del método CFOP. El prototipo se ubicará sobre una superficie estable de trabajo y será operado bajo supervisión durante las pruebas. El usuario conservará el papel central en el entrenamiento: seleccionará el caso, colocará el cubo, esperará la preparación y resolverá manualmente la configuración obtenida.

El escenario no busca demostrar una mejora estadística del aprendizaje ni comparar el desempeño entre grupos de usuarios. Su propósito es verificar que el sistema mecatrónico prepare casos F2L de forma correcta, repetible y segura, y determinar si reduce el tiempo destinado a la preparación manual. La evaluación se realizará con un conjunto acotado de casos definido después del análisis de requisitos.

\subsection{Escenario de uso}

La secuencia de interacción prevista es la siguiente:

\begin{enumerate}
    \item El usuario selecciona en la interfaz uno de los casos F2L disponibles y recibe la indicación para colocar el cubo en la posición de inicio.
    \item El sistema comprueba las condiciones necesarias para iniciar la operación o solicita al usuario corregir la colocación del cubo.
    \item El sistema determina la configuración objetivo del caso y ejecuta la secuencia de movimientos de preparación mediante el mecanismo de manipulación.
    \item Al terminar, el sistema verifica la configuración obtenida con el método seleccionado durante el diseño y comunica al usuario si la preparación fue válida, si requiere recuperación o si ocurrió un fallo.
    \item Cuando la preparación es válida, el usuario retira o utiliza el cubo en la zona de práctica para reconocer y resolver el caso F2L de forma manual.
    \item El usuario puede solicitar la repetición del mismo caso o seleccionar uno diferente para continuar la sesión de práctica.
\end{enumerate}

Este flujo separa la preparación automatizada de la ejecución humana del algoritmo. Así, el sistema actúa como apoyo para presentar situaciones de práctica repetibles y no como un resolvedor autónomo del cubo.

\subsection{Condiciones de prueba}

Las pruebas se efectuarán con cubos Rubik 3 $\times$ 3 compatibles con el mecanismo seleccionado y en una superficie de trabajo definida. Antes de cada ensayo se establecerá una condición inicial documentada para el cubo; puede ser una configuración de referencia o un estado identificado mediante el método de adquisición elegido. Para cada caso se registrarán la configuración objetivo, la secuencia ejecutada, el resultado de verificación, el tiempo de preparación y cualquier incidencia durante la operación.

Los ensayos se organizarán en series de repeticiones consecutivas por caso. El número de casos, el número de repeticiones, las tolerancias de tiempo y los criterios cuantitativos de aceptación se fijarán al terminar el análisis de requisitos y después de obtener una medición base de la preparación manual. Esta decisión evita establecer valores arbitrarios antes de conocer las capacidades del mecanismo y las restricciones del prototipo.

Como referencia de comparación, un practicante preparará manualmente los mismos casos bajo condiciones iniciales equivalentes. El tiempo empleado y la corrección de la configuración se registrarán con el mismo criterio utilizado para el sistema. La comparación se interpretará como evidencia de preparación asistida; no se utilizará para afirmar que el prototipo produce por sí mismo una mejora en la habilidad del usuario.

\subsection{Criterios de validez y alcance de los resultados}

Un ensayo será válido cuando la configuración inicial esté documentada, el caso solicitado pertenezca al conjunto de prueba, la secuencia se ejecute sin intervención no registrada y el estado final pueda verificarse. Si se presenta un fallo, este no se descartará: se clasificará y se incorporará al cálculo de ocurrencia de fallos. Cuando el mecanismo requiera intervención para recuperar el cubo, el hecho se anotará en la bitácora y el ensayo se repetirá únicamente con una nueva condición inicial documentada.

Los resultados permitirán decidir si el concepto seleccionado satisface los requisitos de preparación física de casos F2L y cuáles subsistemas requieren ajuste. No permitirán concluir, sin un estudio posterior con participantes y un diseño experimental pedagógico, que el sistema mejora el aprendizaje, la velocidad de resolución o el rendimiento competitivo de los usuarios.
