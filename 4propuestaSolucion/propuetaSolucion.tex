\section{Propuesta de solución}

Se propone desarrollar un sistema mecatrónico de sobremesa que permita preparar de manera física, controlada y repetible configuraciones seleccionadas de la etapa F2L en un cubo Rubik 3 $\times$ 3. El sistema recibirá del usuario el caso de entrenamiento deseado, determinará una secuencia válida de movimientos para llevar el cubo a la configuración objetivo y ejecutará dicha secuencia mediante un mecanismo de manipulación. Una vez concluida la preparación, el cubo se entregará al usuario para que este identifique y resuelva el caso. Por tanto, la función principal del sistema no será resolver el cubo de forma autónoma, sino reducir el tiempo y la variabilidad asociados a preparar un ejercicio específico.

La propuesta toma como referencia la separación entre percepción, planificación y actuación empleada en robots resolvedores de cubos Rubik \cite{Novakova2018,Gorriz2023}. Asimismo, las métricas de precisión, tiempo y robustez usadas para evaluar la manipulación secuencial del cubo \cite{Yang2020} se adoptarán como base para la verificación del prototipo. La arquitectura se definirá con independencia de las tecnologías particulares que se seleccionen durante el diseño.

\subsection{Operación prevista}

La operación del sistema se organizará en las siguientes etapas:
\begin{enumerate}
    \item El usuario selecciona un caso de F2L incluido en el conjunto de entrenamiento y coloca el cubo en la posición indicada.
    \item El sistema establece la configuración objetivo y obtiene una secuencia de movimientos que la produzca desde una condición de referencia o desde el estado identificado.
    \item El mecanismo ejecuta la secuencia de forma coordinada, mientras el controlador supervisa la finalización de cada movimiento y las condiciones de seguridad.
    \item El sistema verifica la preparación mediante el método de adquisición de estado seleccionado. Si detecta una condición no válida, informa al usuario y ejecuta el procedimiento de recuperación definido.
    \item Al completar la preparación, el usuario retira o utiliza el cubo en la zona de práctica para reconocer y resolver el caso sin intervención del mecanismo.
\end{enumerate}

La propuesta considera inicialmente un conjunto acotado de casos F2L, suficiente para validar la preparación automatizada y repetible. El número de casos, los movimientos permitidos y el método de verificación se definirán a partir de los requisitos y de las restricciones mecánicas del concepto seleccionado.

\subsection{Criterios de diseño y validación}

La selección del concepto se realizará considerando la capacidad de preparar los casos definidos, la compatibilidad con cubos Rubik 3 $\times$ 3 comerciales, la seguridad del usuario, la repetibilidad, la facilidad de manufactura, el mantenimiento y el costo. La validación se relacionará directamente con el problema planteado: se medirá el porcentaje de preparaciones correctas, el tiempo de preparación, la repetibilidad en ensayos consecutivos, los fallos de manipulación y las condiciones de operación segura. Estos resultados se compararán con una medición base de la preparación manual de los mismos casos.

El alcance de la propuesta excluye la resolución autónoma completa del cubo y la demostración de efectos pedagógicos con una muestra de usuarios. Tales aspectos podrán abordarse después de verificar el funcionamiento mecatrónico básico. De igual modo, la extensión a OLL y PLL se mantendrá como posibilidad de trabajo futuro, una vez comprobada la preparación fiable de los casos F2L.
